# Inference-only migration to Qwen3.5-0.8B

## Scope

The generation decoder is replaced with `Qwen/Qwen3.5-0.8B`. The original
VLM-FO1 primary Qwen2.5 vision encoder, auxiliary DaViT encoder, HFRE, and
pretrained projectors are retained. No fine-tuning, alignment training, LoRA,
or optimizer step is performed. The supported CLI, example and Gradio demo
all select Qwen3.5 by default. `--original-decoder` explicitly selects the
original checkpoint for comparison.

The assignment PDF describes region-language alignment training. The scope
for this implementation follows the student's later clarification that training
was excluded.

## Data flow

1. Load an RGB image and 1–100 proposals in original-image pixel coordinates.
   Proposals can be supplied as JSON, drawn in Gradio, or generated by UPN on CUDA.
2. Preprocess the image separately for the two pretrained vision encoders and
   transform the proposal coordinates to the corresponding image resolution.
3. The primary encoder produces image features and intermediate features.
   HFRE combines region features from both encoders using the proposals.
4. Original projectors emit 2048-dimensional image and region vectors.
5. A new linear bridge maps those vectors to Qwen3.5-0.8B's 1024-dimensional
   token-embedding space. The bridge is initialized with a fixed seed.
6. The wrapper inserts these vectors at image and region-feature sentinel
   positions in the prompt. Ordinary text uses Qwen3.5's own token embeddings.
7. Qwen3.5 generates from `inputs_embeds`. The wrapper restores the original
   prompt-ID prefix in the returned tensor, so callers can reliably slice new
   tokens. Stopping criteria receive the same logical prompt prefix.
8. Parsed region indexes select only supplied proposals. Unknown or out-of-range
   indexes do not create boxes. The full raw answer remains in the JSON output.

Generation uses Transformers' official `Qwen3_5ForCausalLM` text decoder.
Qwen3.5's native vision encoder is omitted from the loaded model. All image
and region features come from the retained VLM-FO1 encoders and HFRE.

## Why the bridge is untrained

Compatible tensor widths do not imply compatible feature meanings. A bridge can
make concatenation valid while placing vectors in a space the new decoder has
never learned to interpret. The added `<region0>` through `<region99>` tokens
also have no learned grounding relationship in Qwen3.5. Its padded vocabulary
may already contain rows at the newly assigned IDs; those rows still have not
been trained to mean these region labels. The embedding table is only enlarged
when required and is never shrunk to the tokenizer length.

All inference parameters are frozen and execution uses inference mode. A fixed
seed gives repeatable initialization; it does not train or align the bridge.
An externally supplied bridge state is labeled unverified. An equal-width
identity bridge is likewise not evidence of alignment. Run metadata explicitly
states `fine_tuning_performed: false` and `grounding_quality_validated: false`.

The published VLM-FO1 benchmark scores do not apply to this migration. Neither
fluent output, selected region tags, nor a successful smoke test establishes
object-detection accuracy. No trained Qwen3.5-HFRE checkpoint is included.

## Loading and memory

The replacement path passes `vision_only=True` while constructing FO1. It omits
the original decoder layers, token embeddings, final text norm and language
head before checkpoint materialization. This avoids first loading and then
discarding the old decoder. The retained 826 weight entries exactly match the
published visual stack and contain 1,064,196,928 parameters. The complete source
checkpoint still has to be downloaded because its original shard files also
contain decoder weights.

For Qwen3.5, the official text decoder class selects `text_config` and remaps
the language weights from the published multimodal checkpoint. Its native
vision tensors are skipped, avoiding approximately 384 MiB of parameter
allocation on float32 CPU. This is a weight-memory saving, not a measured
reduction in peak process memory; the published checkpoint download is unchanged.

Loading fails if required retained checkpoint weights are missing or have the
wrong shape, and the Qwen3.5 loader also rejects missing or mismatched decoder
weights. All pretrained visual and decoder components must load; the only
intentionally unaligned additions are the new bridge and region token meanings.

CPU uses float32. CUDA chooses bfloat16 when supported, otherwise float16.
CUDA-only 4-bit/8-bit loading uses an explicit `BitsAndBytesConfig`. SDPA is the
portable attention default. FlashAttention is optional and is not installed by
the Docker images.

## Transformers 5 compatibility

Dependencies pin Transformers 5.2.0, which supplies Qwen3.5. Compatibility fixes
in the vendored FO1 implementation cover:

- Using its original flat Qwen2.5 configuration, instead of the public
  Transformers 5 configuration that moved text attributes into `text_config`.
- Preserving the original rotary-position frequency formula after Transformers
  removed `default` from its RoPE initializer registry.
- Reinitializing non-persistent rotary buffers after meta loading and rejecting
  non-finite visual features before generation.
- Using the Transformers 5 dictionary form for tied-weight mappings.
- Creating DaViT's drop-path schedule on CPU during meta-device initialization.
- Supplying legacy token-ID defaults and a vision-weight initialization default.
- Lazy imports, explicit device checks, proposal validation before tokenization,
  and correct image accumulation for a single-image conversation history.
- Using the current cache API for the optional original decoder's incremental
  image generation and preserving cache positions during text generation.

These changes preserve the published visual tensor names and dimensions.
Regression tests compare all 1,261 published checkpoint keys, round-trip a small
checkpoint through `from_pretrained`, and run its real primary vision encoder.
See [validation](validation.md) for the distinction between these checks,
real-decoder smoke testing, and complete pretrained inference.

## Main files

- `vlm_fo1/model/builder.py`: checkpoint loading and decoder selection.
- `vlm_fo1/model/language_model/qwen35_fo1_wrapper.py`: frozen feature bridge and generation.
- `vlm_fo1/model/language_model/omchat_qwen2_5_vl.py`: retained FO1 architecture and vision-only loading.
- `vlm_fo1/mm_utils.py`: prompt assembly, preprocessing and coordinate conversion.
- `vlm_fo1/runtime.py`: shared runtime, validation and run metadata.
- `tests/`: offline contract, checkpoint compatibility and generation tests.
